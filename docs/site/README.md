# Documentation website

This directory owns a curated, dependency-free documentation website for the
managed `platform-vpc-controller` v0.1.0 line. Content is English; the existing
Traditional Chinese engineering diagrams and speaker notes are first-class
pages. Historical D / OVN-IC installation guides are not mixed into this site.

## Build and preview

From the repository root:

```sh
python3 scripts/build-docs.py --output public
python3 -m http.server 8000 --directory public
```

Open `http://localhost:8000/`. For source links, provide the actual repository:

```sh
python3 scripts/build-docs.py --output public --repository OWNER/REPOSITORY --ref main
```

The default repository is `yckao/kube-ovn-global-vpc`; `GITHUB_REPOSITORY` or
`--repository` overrides it for a fork. Curated source files are downloadable
without leaving the site; other source references link to the configured repo.

All internal links are relative, so the output works at a custom domain root,
under GitHub project Pages (`/REPOSITORY/`), and from local static preview. There
are no runtime CDN, external font, analytics or server dependencies. Search is
built into `search-index.js` and works without a backend. JavaScript is optional
for reading; it adds local search, theme switching and mobile navigation.

## Validation

```sh
python3 scripts/build-docs.py --output public --check
```

Every build checks local links and fragments, source allowlists, copied files
and asset references. `--check` additionally fails on an empty or missing page,
missing search entries, and forbidden private-output paths. Preview both desktop
and narrow widths after changing layout. The GitHub Pages workflow builds and
uploads only `public/`; raw `artifacts/` and environment handoff material never
enter the output.

## Publishing

`.github/workflows/docs.yml` prepares the GitHub Pages artifact. Enable Pages
with **GitHub Actions** in the repository settings, then use the workflow after
reviewing the public tree. The workflow's environment protection and repository
settings control publication. A local successful build is not a deployed site.

## Editorial contract

- Only files in the builder's explicit page/download allowlists are published.
- Imported Markdown is rendered with escaped raw HTML and safe URL handling.
- Private artifact or environment-handoff links are rejected at build time;
  no raw evidence file is copied or automatically exposed.
- New design claims belong in `content/` with implementation/evidence references.
- Keep process availability, API acknowledgement and packet evidence separate.
- Diagrams are copied from their manifest; source files are not regenerated by
  a documentation build.

The small Markdown renderer supports the subset used by these docs: headings,
paragraphs, fenced code, tables, lists, block quotes, links/images, emphasis and
inline code. It intentionally does not execute plugins or arbitrary HTML.
