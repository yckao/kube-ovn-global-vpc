# Build and install the native Kube-OVN extension

The supported administrator interface is the project's Helm extension chart,
used directly or through [vpcctl](vpcctl.md). Follow the
[managed quick start](managed-quickstart.md) for prebuilt image installation,
upgrades, rollback and removal. This page retains the **maintainer build and
low-level recovery reference**; its build tools are not end-user prerequisites.

The patch changes Kube-OVN source. Release CI builds a replacement controller,
packages it in a matched image, and includes the two schema properties in the
extension chart's native bundle. There is no runtime configuration switch that
adds this behavior to an unmodified stock binary.

| Artifact | What it runs | Where it is installed |
|---|---|---|
| Patched native Kube-OVN image, built here | `kube-ovn-controller` with `destination-routes.v1` | Existing native controller Deployment in each Infra |
| Platform controller image | `platform-vpc-controller` | Management authority and local operators |
| Gateway image | Managed gateway runtime | Gateway Pods generated by the local operators |

This guide covers a **first installation with no active destination-route
intent**, using Linux/amd64 build and target nodes. It is an evaluation procedure,
not an unattended installer or a production qualification claim. The v1.16.3
compatibility builder is amd64-only. Other architectures need a separate build
and runtime qualification.

The earlier Lab deployment mounted a rebuilt executable into the original
container with a read-only hostPath. That was a temporary experiment and was
restored to stock. The OCI packaging procedure below is the installation recipe;
it must be tested against your image/runtime and is not evidence that this exact
recipe has already been deployed. The release pipeline can publish prebuilt patched images and chart bundles;
implementation of that pipeline does not establish that a release has been
published or deployed. A portable real-OVN qualification harness is still absent.

Read in order: [baseline](#1-identify-the-installed-baseline-and-its-owner),
[source](#2-fetch-and-verify-the-exact-source), [build/tests](#3-build-and-run-the-native-tests),
[image](#4-package-a-matching-native-controller-image),

[acknowledgement](#7-return-to-the-managed-quick-start-and-verify-acknowledgement)
and [rollback](#8-withdraw-and-roll-back).

## 1. Identify the installed baseline and its owner

Use Bash on a Linux/amd64 build host with Git, the matching Go toolchain, Python
3.11+, venv/pip, Helm, jq, kubectl, Docker/buildx and registry access. Run from a
full checkout of this repository; installation bundles are not full source trees.
You need administrative access to the target Infra, including its native OVN
database inspection path. Existing local Pod networking must already work.

The commands below directly update an administrator-owned evaluation Deployment
and CRD. If Helm, Flux, a ClusterResourceSet or another reconciler owns these
fields, first make the same image/schema changes in that owner's desired state
and coordinate reconciliation. A live patch alone will be reverted. Do not change
a shared image setting that also upgrades CNI, OVS or ovn-central inadvertently.

```sh
set -euo pipefail
umask 077
export REPO=$(pwd)
export NATIVE_WORK=$(mktemp -d /tmp/gvpc-native.XXXXXX)
export SITE_CTX=infra-a
export NATIVE_NS=kube-system
export NATIVE_DEPLOY=kube-ovn-controller
export NATIVE_CONTAINER=kube-ovn-controller
export NATIVE_SELECTOR=app=kube-ovn-controller
export SITE_WORK="$NATIVE_WORK/$SITE_CTX"
mkdir "$SITE_WORK"

kubectl --context "$SITE_CTX" -n "$NATIVE_NS" get deployment "$NATIVE_DEPLOY" \
  -o json > "$SITE_WORK/deployment.before.json"
kubectl --context "$SITE_CTX" get crd vpcs.kubeovn.io \
  -o json > "$SITE_WORK/crd.before.json"
kubectl --context "$SITE_CTX" get vpcs.kubeovn.io \
  -o json > "$SITE_WORK/vpcs.before.json"
kubectl --context "$SITE_CTX" -n "$NATIVE_NS" get pods -l "$NATIVE_SELECTOR" \
  -o json > "$SITE_WORK/pods.before.json"
jq -e 'all(.items[]; ((.spec.destinationRoutes // []) | length) == 0)' \
  "$SITE_WORK/vpcs.before.json"
jq --arg c "$NATIVE_CONTAINER" \
  '.items[] | {pod: .metadata.name, node: .spec.nodeName,
    image: [.spec.containers[] | select(.name==$c) | .image],
    imageID: [.status.containerStatuses[]? | select(.name==$c) | .imageID]}' \
  "$SITE_WORK/pods.before.json"
for pod in $(jq -r '.items[].metadata.name' "$SITE_WORK/pods.before.json"); do
  kubectl --context "$SITE_CTX" -n "$NATIVE_NS" exec "$pod" -c "$NATIVE_CONTAINER" -- \
    sha256sum /kube-ovn/kube-ovn-controller > "$SITE_WORK/$pod.original-binary.sha256"
  kubectl --context "$SITE_CTX" -n "$NATIVE_NS" exec "$pod" -c "$NATIVE_CONTAINER" -- \
    getcap /kube-ovn/kube-ovn-controller > "$SITE_WORK/$pod.original-capabilities.txt"
done
```

Check the Deployment's owning release, container command/args, image provenance,
startup version logs, node architecture, probes, security context and mounts.
An old hostPath mount over `/kube-ovn/kube-ovn-controller` would hide a new image's
binary and must be resolved before using this recipe. Keep these snapshots private
and retain them outside temporary storage for the duration of the evaluation.

Select the extension by **actual controller source**, not the version of CNI,
OVS, ovn-central or an image tag alone:

| Target | Exact upstream commit | Go toolchain | Integration directory |
|---|---|---|---|
| v1.16.3 compatibility | `98af25ffae49193a8dc16bbc39bd8ca4110ec367` | 1.26.6 | `integration/kube-ovn/compat-v1.16.3` |
| v1.16.4 | `a9296ef2a37c6519bc0ecb798082ce139c72f8eb` | 1.27.1 | `integration/kube-ovn` |

If your vendor build has different source or dependency patches, neither row
establishes compatibility. Review and qualify a new source lock first. Do not
bypass a source mismatch or use `--reject`/fuzzy application to continue.

## 2. Fetch and verify the exact source

Choose one target. Replace the Go path with the matching installed toolchain.
Keep all variables in the same shell throughout this guide.

```sh
export NATIVE_TARGET=v1.16.3
export GO_BIN=/opt/go1.26.6/bin/go
case "$NATIVE_TARGET" in
  v1.16.3) export NATIVE_INTEGRATION="$REPO/integration/kube-ovn/compat-v1.16.3" ;;
  v1.16.4) export NATIVE_INTEGRATION="$REPO/integration/kube-ovn" ;;
  *) echo 'Choose a reviewed source target' >&2; exit 1 ;;
esac
export NATIVE_COMMIT=$(jq -r .commit "$NATIVE_INTEGRATION/source-lock.json")
export NATIVE_SOURCE="$NATIVE_WORK/upstream"
git clone --no-checkout "$(jq -r .repository "$NATIVE_INTEGRATION/source-lock.json")" "$NATIVE_SOURCE"
git -C "$NATIVE_SOURCE" checkout --detach "$NATIVE_COMMIT"
test -z "$(git -C "$NATIVE_SOURCE" status --porcelain)"
python3 "$NATIVE_INTEGRATION/scripts/apply.py" "$NATIVE_SOURCE" --check
sha256sum "$NATIVE_INTEGRATION/native.patch" > "$NATIVE_WORK/patch.sha256"
"$GO_BIN" version
```

`--check` verifies the commit, locked original-file hashes and `git apply --check`;
it does not edit the source. For v1.16.3, leave this checkout **unpatched**: its
builder applies the patch in a separate production copy. For v1.16.4, the next
section explicitly patches this checkout.

## 3. Build and run the native tests

Use only the branch matching the selected target. Disable ambient Go workspace
and flag overrides so the production build uses the pinned module graph.

```sh
export GOTOOLCHAIN=local GOWORK=off GOENV=off GOFLAGS=
export PATH="$(dirname "$GO_BIN"):$PATH"
export NATIVE_BUILD="$NATIVE_WORK/build"
```

For **v1.16.3**:

```sh
test "$NATIVE_TARGET" = v1.16.3
python3 "$NATIVE_INTEGRATION/scripts/build.py" "$NATIVE_SOURCE" \
  --go "$GO_BIN" --output "$NATIVE_BUILD"
export PATCHED_SOURCE="$NATIVE_BUILD/production-source"
export NATIVE_BINARY="$NATIVE_BUILD/kube-ovn-controller"
mkdir "$NATIVE_BUILD/test-tmp"
TMPDIR="$NATIVE_BUILD/test-tmp" "$NATIVE_BUILD/ovs.test" \
  -test.run '^TestNativeDestinationRoutes$' -test.v | tee "$NATIVE_BUILD/ovs-test.log"
TMPDIR="$NATIVE_BUILD/test-tmp" "$NATIVE_BUILD/controller.test" \
  -test.run '^TestDestinationRoute(Validation|OrphanGuardGC)$' -test.v | tee "$NATIVE_BUILD/controller-test.log"
TMPDIR="$NATIVE_BUILD/test-tmp" "$NATIVE_BUILD/destinationroute.test" \
  -test.v | tee "$NATIVE_BUILD/planner-test.log"
```

The builder compiles tests but does not execute them. The three commands above
execute the Linux test binaries; `set -o pipefail` makes a failure stop the guide.
The builder's `runtimeTestsExecuted: false` describes its own build stage; retain
the subsequent test logs separately. Do not use the parent v1.16.4 test wrapper
on this target: the pinned libovsdb versions differ.

For **v1.16.4**:

```sh
test "$NATIVE_TARGET" = v1.16.4
test "$("$GO_BIN" env GOVERSION)" = go1.27.1
python3 "$NATIVE_INTEGRATION/scripts/apply.py" "$NATIVE_SOURCE"
export PATCHED_SOURCE="$NATIVE_SOURCE"
mkdir "$NATIVE_BUILD"
bash "$NATIVE_INTEGRATION/scripts/test.sh" "$PATCHED_SOURCE" | tee "$NATIVE_BUILD/native-tests.log"
export NATIVE_BINARY="$NATIVE_BUILD/kube-ovn-controller"
NATIVE_PATCH_SHA=$(sha256sum "$NATIVE_INTEGRATION/native.patch" | cut -d ' ' -f 1)
NATIVE_BUILD_DATE=$(date -u +%Y-%m-%d_%H:%M:%S)
(
  cd "$PATCHED_SOURCE"
  CGO_ENABLED=0 GOOS=linux GOARCH=amd64 "$GO_BIN" build \
    -mod=readonly -trimpath -buildmode=pie \
    -ldflags "-w -s -extldflags '-z now' -X github.com/kubeovn/kube-ovn/versions.COMMIT=git-${NATIVE_COMMIT}+globalvpc-${NATIVE_PATCH_SHA:0:12} -X github.com/kubeovn/kube-ovn/versions.VERSION=v1.16.4-globalvpc.v1 -X github.com/kubeovn/kube-ovn/versions.BUILDDATE=$NATIVE_BUILD_DATE" \
    -o "$NATIVE_BINARY" ./cmd/controller
  git diff --exit-code -- go.mod go.sum
)
```

Both test paths correct in-memory OVSDB test-server fixtures in disposable test
copies. **Do not ship a controller built from those test copies.** The v1.16.4
wrapper's internal build is a test check; the explicit production build above
uses the original dependencies. See the [test boundary](../integration/kube-ovn/README.md#apply-and-test).

Record the binary, source, dependency manifests and patch together:

```sh
"$GO_BIN" version -m "$NATIVE_BINARY" > "$NATIVE_BUILD/controller-build-info.txt"
sha256sum "$NATIVE_BINARY" "$PATCHED_SOURCE/go.mod" "$PATCHED_SOURCE/go.sum" \
  > "$NATIVE_BUILD/production.sha256"
cp "$NATIVE_INTEGRATION/source-lock.json" "$NATIVE_BUILD/source-lock.json"
cp "$NATIVE_INTEGRATION/native.patch" "$NATIVE_BUILD/native.patch"
```

These tests establish planner and transaction behavior, not packet forwarding.
Before rollout, qualify this binary/dependency combination with isolated real
NB/SB databases and northd: atomic create/withdraw, BFD UUID replacement, each
gateway up/down combination, both child-prefix ECMP groups, all-down parent
discard, and preservation of unrelated default/NAT state. The repository's
[native qualification contract](../integration/kube-ovn/README.md#real-ovsdb-and-northd-qualification)
defines this gate; an environment-specific harness is still required. Do not
report unit-test success as completion of this gate.

## 4. Package a matching native-controller image

Use the exact **native controller distribution image** established in step 1 as
the base, pinned by digest. This preserves its scripts and runtime dependencies.
The template assumes the upstream layout and a root-default image build user;
inspect a vendor image before adapting it. It changes only the controller
executable, preserving `/kube-ovn/start-controller.sh` and the other binaries.
The pinned upstream executable requires `cap_net_bind_service,cap_net_raw=eip`.

```sh
export NATIVE_BASE=REGISTRY/kube-ovn@sha256:REPLACE_WITH_VERIFIED_BASE_DIGEST
export NATIVE_IMAGE_REPO=REGISTRY/kube-ovn-globalvpc
export NATIVE_IMAGE_TAG="$NATIVE_IMAGE_REPO:${NATIVE_TARGET}-globalvpc.v1"
printf '%s\n' "$NATIVE_BASE" > "$SITE_WORK/original-image.txt"
mkdir "$NATIVE_WORK/image"
cp "$NATIVE_BINARY" "$NATIVE_WORK/image/kube-ovn-controller"
cat > "$NATIVE_WORK/image/Dockerfile" <<'DOCKERFILE'
ARG NATIVE_BASE
FROM ${NATIVE_BASE}
COPY --chown=0:0 --chmod=0755 kube-ovn-controller /kube-ovn/kube-ovn-controller
RUN setcap cap_net_bind_service,cap_net_raw=eip /kube-ovn/kube-ovn-controller \
    && getcap /kube-ovn/kube-ovn-controller
DOCKERFILE
docker buildx build --platform linux/amd64 \
  --build-arg NATIVE_BASE="$NATIVE_BASE" \
  --metadata-file "$NATIVE_WORK/image/build-metadata.json" \
  -t "$NATIVE_IMAGE_TAG" --push "$NATIVE_WORK/image"
NATIVE_DIGEST=$(jq -er '."containerimage.digest"' "$NATIVE_WORK/image/build-metadata.json")
export NATIVE_IMAGE="$NATIVE_IMAGE_REPO@$NATIVE_DIGEST"
docker run --rm --platform linux/amd64 --network none --entrypoint /bin/sh \
  "$NATIVE_IMAGE" -ec \
  'sha256sum /kube-ovn/kube-ovn-controller; getcap /kube-ovn/kube-ovn-controller'
```

Compare the image's binary hash to `production.sha256`, verify both capabilities,
and retain the base digest, candidate digest, Dockerfile and build metadata.
Copying an executable can strip file capabilities; a successful image build is
not enough. Retain the exact original image digest for rollback and ensure the
nodes can pull both images. Preserve the Deployment's existing capability,
non-root, privilege-escalation and probe settings.

## 5. Add only the two CRD properties

Render the patched chart **locally** to extract the two schema fragments. Do not
install the chart or apply its complete CRD bundle over the existing cluster.
Create a private Python environment for the YAML parser:

```sh
python3 -m venv "$NATIVE_WORK/venv"
"$NATIVE_WORK/venv/bin/pip" install 'PyYAML==6.0.2'
export SCHEMA_PYTHON="$NATIVE_WORK/venv/bin/python"
helm template native-schema "$PATCHED_SOURCE/charts/kube-ovn" > "$NATIVE_WORK/patched-chart.yaml"
```

The following local generator accepts only a single served/storage `v1` schema
with existing `bfdPort`, refuses already-present extension fields, and emits
JSON Patch operations guarded by CRD UID and resourceVersion. Other CRD version
or conversion layouts require an explicit review instead of this example.

```sh
kubectl --context "$SITE_CTX" get crd vpcs.kubeovn.io -o json > "$SITE_WORK/crd.current.json"
"$SCHEMA_PYTHON" - <<'PY'
import json, os
from pathlib import Path
import yaml
work, site = Path(os.environ['NATIVE_WORK']), Path(os.environ['SITE_WORK'])
docs = list(yaml.safe_load_all((work / 'patched-chart.yaml').read_text()))
source = next(d for d in docs if d and d.get('metadata', {}).get('name') == 'vpcs.kubeovn.io')
current = json.loads((site / 'crd.current.json').read_text())
versions = current['spec']['versions']
assert len(versions) == 1 and versions[0]['name'] == 'v1'
assert versions[0]['served'] and versions[0]['storage']
assert current['spec'].get('conversion', {}).get('strategy', 'None') == 'None'
props = versions[0]['schema']['openAPIV3Schema']['properties']
assert 'bfdPort' in props['spec']['properties']
source_props = next(v for v in source['spec']['versions'] if v['name'] == 'v1')['schema']['openAPIV3Schema']['properties']
patch = [
    {'op': 'test', 'path': '/metadata/uid', 'value': current['metadata']['uid']},
    {'op': 'test', 'path': '/metadata/resourceVersion', 'value': current['metadata']['resourceVersion']},
]
for section in ('spec', 'status'):
    assert 'destinationRoutes' not in props[section]['properties'], 'Extension already present; inspect before updating'
    patch.append({'op': 'add',
        'path': f'/spec/versions/0/schema/openAPIV3Schema/properties/{section}/properties/destinationRoutes',
        'value': source_props[section]['properties']['destinationRoutes']})
(site / 'crd-add.patch.json').write_text(json.dumps(patch, indent=2) + '\n')
PY
kubectl --context "$SITE_CTX" patch crd vpcs.kubeovn.io --type=json \
  --patch-file "$SITE_WORK/crd-add.patch.json" --dry-run=server -o json \
  > "$SITE_WORK/crd.dry-run.json"
```

Review the patch and dry-run result. This comparison must print no differences;
it strips only the two intended additions before comparing the complete CRD spec:

```sh
diff -u <(jq -S .spec "$SITE_WORK/crd.current.json") \
  <(jq -S '.spec | del(.versions[0].schema.openAPIV3Schema.properties.spec.properties.destinationRoutes,
                      .versions[0].schema.openAPIV3Schema.properties.status.properties.destinationRoutes)' \
      "$SITE_WORK/crd.dry-run.json")
kubectl --context "$SITE_CTX" patch crd vpcs.kubeovn.io --type=json \
  --patch-file "$SITE_WORK/crd-add.patch.json"
kubectl --context "$SITE_CTX" get crd vpcs.kubeovn.io -o json > "$SITE_WORK/crd.after.json"
diff -u <(jq -S .spec "$SITE_WORK/crd.dry-run.json") <(jq -S .spec "$SITE_WORK/crd.after.json")
```

If the resourceVersion test fails, collect a fresh snapshot, inspect the concurrent
change, regenerate the patch and repeat dry-run. Do not remove the precondition.
Persist these two schema additions in the CRD owner's desired state as well.

## 6. Replace the native controller replicas

Do this while destination-route intent is still absent. Save a fresh Deployment
snapshot and generate a guarded patch changing only the selected container image.
The container index is discovered by name; no ordering assumption is required.

```sh
kubectl --context "$SITE_CTX" get vpcs.kubeovn.io -o json | \
  jq -e 'all(.items[]; ((.spec.destinationRoutes // []) | length) == 0)'
kubectl --context "$SITE_CTX" -n "$NATIVE_NS" get deployment "$NATIVE_DEPLOY" \
  -o json > "$SITE_WORK/deployment.current.json"
jq --arg c "$NATIVE_CONTAINER" --arg image "$NATIVE_IMAGE" '
  (.spec.template.spec.containers | map(.name) | index($c)) as $i |
  if $i == null then error("native container missing") else
  [{op:"test", path:"/metadata/uid", value:.metadata.uid},
   {op:"test", path:"/spec/template", value:.spec.template},
   {op:"replace", path:("/spec/template/spec/containers/"+($i|tostring)+"/image"), value:$image}]
  end' "$SITE_WORK/deployment.current.json" > "$SITE_WORK/deployment-image.patch.json"
kubectl --context "$SITE_CTX" -n "$NATIVE_NS" patch deployment "$NATIVE_DEPLOY" \
  --type=json --patch-file "$SITE_WORK/deployment-image.patch.json" --dry-run=server -o json \
  > "$SITE_WORK/deployment.dry-run.json"
diff -u <(jq -S '.spec.template' "$SITE_WORK/deployment.current.json") \
  <(jq -S '.spec.template' "$SITE_WORK/deployment.dry-run.json") || test "$?" = 1
```

The expected diff is **one image value only**. Preserve command/args, environment,
volumes, ServiceAccount, security context, probes and leader-election identity.
Inspect the current rollout strategy and plan for its actual availability effect;
this guide does not change it or promise uninterrupted reconciliation.

```sh
kubectl --context "$SITE_CTX" -n "$NATIVE_NS" patch deployment "$NATIVE_DEPLOY" \
  --type=json --patch-file "$SITE_WORK/deployment-image.patch.json"
kubectl --context "$SITE_CTX" -n "$NATIVE_NS" rollout status deployment/"$NATIVE_DEPLOY" --timeout=300s
kubectl --context "$SITE_CTX" -n "$NATIVE_NS" get pods -l "$NATIVE_SELECTOR" \
  -o json > "$SITE_WORK/pods.after.json"
jq -e --arg c "$NATIVE_CONTAINER" --arg image "$NATIVE_IMAGE" '
  (.items | length) > 0 and all(.items[];
    .metadata.deletionTimestamp == null and
    any(.spec.containers[]; .name==$c and .image==$image) and
    any(.status.containerStatuses[]?; .name==$c and .ready==true))' "$SITE_WORK/pods.after.json"
for pod in $(jq -r '.items[].metadata.name' "$SITE_WORK/pods.after.json"); do
  kubectl --context "$SITE_CTX" -n "$NATIVE_NS" exec "$pod" -c "$NATIVE_CONTAINER" -- \
    sha256sum /kube-ovn/kube-ovn-controller
  kubectl --context "$SITE_CTX" -n "$NATIVE_NS" exec "$pod" -c "$NATIVE_CONTAINER" -- \
    getcap /kube-ovn/kube-ovn-controller
done
```

Wait and repeat the Pod check if old Pods are still terminating. Compare every
running binary hash with the build, inspect startup logs for the custom version,
and verify existing Pod IP/allocation records and baseline local packet tests.
All replicas must be replaced before managed intent is enabled; a stock replica
must not regain leadership with active extension routes. Do not start another
native controller Deployment with a different election identity.

For Infra B, keep the build variables and switch only the site variables:

```sh
export SITE_CTX=infra-b
export SITE_WORK="$NATIVE_WORK/$SITE_CTX"
mkdir "$SITE_WORK"
```

Repeat the snapshot/check commands in step 1 and steps 5–6, using this site's
actual namespace, Deployment, container and selector. Do not rerun the workspace
initialization or overwrite Infra A's snapshots. Reuse the build/image only if
this Infra has the same verified source, runtime base and architecture; record
its confirmed original digest in its own `original-image.txt`. Otherwise use a
separate workspace and perform its matching build.

## 7. Return to the managed quick start and verify acknowledgement

Continue with the authority and site installation in the
[managed quick start](managed-quickstart.md#install-native-integration-and-the-authority),
using prebuilt platform/gateway images. Skip its native-extension chart install
if you installed that extension manually using this reference: the chart cannot
invent the original stock-state receipt for an already modified installation.
Do not apply [example-vpc.yaml](../integration/kube-ovn/example-vpc.yaml)
as a standalone connectivity test: it assumes existing connected transit ports,
gateways and suitable native BFD HA chassis. The managed operators create those
resources from the registered locations and reserved pools.

After creating the managed example, resolve its native VPC through public Subnet
status. `AUTH_CTX` was defined in the managed quick start:

```sh
export SITE_CTX=infra-a
export SITE_WORK="$NATIVE_WORK/$SITE_CTX"
export NATIVE_VPC=$(kubectl --context "$AUTH_CTX" -n project-demo \
  get subnet.platform.globalvpc.io app-a -o jsonpath='{.status.nativeVpcName}')
test -n "$NATIVE_VPC"
kubectl --context "$SITE_CTX" get vpc.kubeovn.io "$NATIVE_VPC" \
  -o json > "$SITE_WORK/native-vpc.json"
python3 - <<'PY'
import hashlib, json, os
from pathlib import Path
vpc = json.loads((Path(os.environ['SITE_WORK']) / 'native-vpc.json').read_text())
routes = []
for r in sorted(vpc['spec'].get('destinationRoutes') or [], key=lambda r: r['cidr']):
    routes.append({'cidr': r['cidr'], 'nextHops': sorted(r['nextHops']),
        'bfd': {k: r['bfd'][k] for k in ('minRX', 'minTX', 'multiplier')},
        'selectionFields': sorted(r['selectionFields'])})
assert routes, 'This cross-location example must have nonempty intent'
expected = hashlib.sha256(json.dumps(routes, separators=(',', ':')).encode()).hexdigest()
ack = vpc.get('status', {}).get('destinationRoutes', {})
assert ack.get('capability') == 'destination-routes.v1', ack
assert ack.get('ready') is True, ack
assert ack.get('observedGeneration') == vpc['metadata']['generation'], ack
assert ack.get('appliedHash') == expected, ack
print('Current native intent acknowledged:', vpc['metadata']['name'], expected)
PY
```

Use `app-a` with the Infra A context and `app-b` with Infra B. If pending, inspect
native controller and local operator logs, then fetch a fresh object and recheck.
The local operator additionally checks the native hash against its desired
binding. Complete the quick start's **bidirectional ICMP and HTTP packet tests**;
Deployment readiness and this acknowledgement do not prove BFD or forwarding.
Then use the [validation guide](managed-validation.md) for single-gateway loss,
all-gateways-down discard, restoration, MTU, tenant isolation and lifecycle tests.

| Symptom | Check |
|---|---|
| Source mismatch / patch does not apply | Exact source commit and original-file hashes; do not force the patch |
| `NativeCapabilityRequired` | Correct cluster CRD, both added fields, installed image/binary and source target |
| `NativeRoutesPending` | Capability, generation, expected hash, native logs, connected next hops and ownership conflicts |
| New image but old behavior | Old leader replicas, hostPath hiding the executable, incorrect container selection |
| Controller cannot start | Executable architecture/capabilities, unchanged probes/args and original runtime dependencies |
| ACK passes but packets fail | Gateway readiness, real BFD state, underlay/transport ports, MTU and return path |

## 8. Withdraw and roll back

Rollback removes cross-location connectivity. Keep the patched native controller
and managed operators running while draining. For **every** managed VPC using
this extension, follow the quick start's [deletion sequence](managed-quickstart.md#drain-and-remove):
workloads, public Subnets, then public VPC. Do not delete internal bindings or
remove finalizers. The owner waits for native empty-intent acknowledgement before
tearing down its remaining resources. Unavailable locations can block this step.

For an independently administered native VPC with no materializing operator,
its owner may set `spec.destinationRoutes: []`. Before changing `bfdPort`, require
`ready: true`, capability `destination-routes.v1`, the current observed generation
